# Pacer GPX Player

Скрипт на Python для проигрывания GPX-треков в Android-эмулятор. Шлёт в эмулятор GPS-координаты, ритмичные данные акселерометра и гироскопа (как при ходьбе), а также атмосферное давление по высоте — чтобы фитнес-приложения вроде Pacer записывали активность так, будто это настоящая прогулка с реальным маршрутом, шагами и рельефом.

## Требования

- **Android Studio** с настроенным AVD (тестировалось на Pixel 8). В Advanced Settings AVD должен быть включён сенсор **Atmospheric Pressure** — без него не будет рельефа.
- **Python 3.13+**. Никаких внешних библиотек, всё на стандартной библиотеке.
- Фитнес-приложение, установленное на эмуляторе (Pacer или аналог), с разрешённой геолокацией.

## Файлы в репозитории

| Файл | Описание |
|------|----------|
| `gpx_player.py` | Основной скрипт: парсит GPX, интерполирует точки, шлёт координаты и симулирует сенсоры |
| `test.py` | Минимальная проверка связи с консолью эмулятора |
| `humanize.py` | Превращает идеальный маршрут в «человеческий»: остановки, шум скорости и GPS |
| `setup_headless.sh` | Установка и запуск эмулятора без Android Studio (только консольный SDK) |
| `tests/` | Юнит-тесты парсера, интерполяции и барометра (`python -m unittest discover -s tests`) |

## Настройка

1. Запусти эмулятор. Запомни порт из заголовка окна (обычно `5554`).

2. Получи токен консоли эмулятора:

   ```bash
   # Windows
   type %USERPROFILE%\.emulator_console_auth_token

   # macOS / Linux
   cat ~/.emulator_console_auth_token
   ```

3. Токен подхватывается автоматически из `~/.emulator_console_auth_token`. При необходимости его можно передать явно (`--token` или переменная `EMULATOR_AUTH_TOKEN`), порт — через `--port`.

4. На эмуляторе установи фитнес-приложение через Play Store, войди в аккаунт.

5. Выдай приложению разрешения:
   - Settings → Apps → [твоё приложение] → Permissions → Location → **Allow all the time**
   - Physical activity → On
   - Settings → Location → Use location → On, режим High accuracy

## Проверка связи

```bash
python test.py
```

Ожидаемый вывод — три блока с `OK`. На эмуляторе в Google Maps синяя точка должна прыгнуть на координаты, заданные в скрипте.

## Без Android Studio (headless)

```bash
./setup_headless.sh install   # один раз: SDK, системный образ, AVD с барометром
./setup_headless.sh start     # эмулятор без окна
adb install pacer.apk         # поставить приложение
python gpx_player.py track.gpx
```

Нужны Java 17+, curl, unzip и аппаратная виртуализация (KVM). Скрипт не проверялся на всех ОС — при проблемах смотри `~/android-sdk/emulator.log`. Так же его можно запустить на сервере или в CI.

## Проверка трека без эмулятора

```bash
python gpx_player.py track.gpx --dry-run
```

Покажет число точек, перепад высот, длительность, дистанцию и среднюю скорость. Если в GPX нет `<time>`, время считается из длины пути и `--walk-kmh` (по умолчанию 4.5).

## Режим humanize: «человеческая» прогулка

```bash
python gpx_player.py track.gpx --humanize --seed 42 --walk-kmh 4.8 --stop-prob 0.6
```

Скрипт берёт из GPX только геометрию и проходит её заново:

- скорость плавает вокруг средней (`--walk-kmh`), а не постоянна;
- на поворотах и перекрёстках с вероятностью `--stop-prob` человек ждёт 5–40 с (светофор, поток машин), перед этим притормаживает;
- изредка бывают короткие остановки на 3–10 с;
- GPS шумит и дрейфует (`--gps-noise`, метры);
- во время стоянки акселерометр и гироскоп переключаются в режим «стоим», шаги не идут.

`--seed` делает результат воспроизводимым. Остановки определяются только по форме маршрута (поворотам): реальные светофоры и переходы из карт скрипт не берёт. Для этого можно в будущем подтянуть данные OpenStreetMap (`highway=traffic_signals`, `highway=crossing`) через Overpass API.

## Создание GPX-маршрута

Самый удобный способ собрать GPX-файл — через [**gpx.studio**](https://gpx.studio/) (бесплатный онлайн-редактор GPX-треков прямо в браузере, регистрация не нужна).

1. Открой [gpx.studio](https://gpx.studio/) и в левой панели нажми **Create new file** (или сразу начни кликать по карте).

2. На панели инструментов слева убедись, что выбран режим **Routing** (карандаш с линией) и тип маршрута — **Walking** (пешеходный). Это нужно, чтобы маршрут прокладывался по тротуарам и пешеходным дорожкам, а не по автомагистралям.

3. Кликни на карте начальную точку → последовательно кликай по промежуточным точкам до конечной. После каждого клика gpx.studio автоматически прокладывает между ними пеший маршрут по реальной уличной сети.

4. На правой панели проверь общую длину маршрута. Для пешей прогулки обычно 1–4 км.

5. **Самое важное для этого скрипта — задать таймстампы.** Без них скрипт не будет знать, с какой скоростью «идти». Открой панель **Time** (часики на левой панели или в меню) и:
   - Выстави **Start time** — например, `09:30` нужного дня.
   - Выбери способ задания: **Total time** (укажи общую длительность, например 30 минут) либо **Speed** (укажи среднюю скорость, например 4 км/ч).
   - Жми **Apply** — gpx.studio распределит таймстампы по всем точкам маршрута пропорционально.

6. Если нужно, в той же панели Time можно добавить паузу на остановки, чтобы маршрут выглядел естественнее.

7. Экспортируй: меню в левом верхнем углу → **Export** → **Download GPX**. Сохрани файл рядом с `gpx_player.py`.

После этого можно сразу запускать `python gpx_player.py твой_файл.gpx`.

### Советы

- **Высоты подтянутся автоматически.** gpx.studio добавляет в каждую точку реальную высоту из карты высот (SRTM). Скрипт использует их для симуляции барометра.
- **Темп ходьбы 4–5 км/ч** выглядит естественно. Меньше 3 — подозрительно медленно, больше 6 — уже не ходьба.
- **Если нужно несколько одинаковых маршрутов на разные дни** — построй один раз, сохрани, потом просто меняй Start date в панели Time и экспортируй заново под другим именем (`12_05.gpx`, `13_05.gpx` и т.д.).

## Использование

1. Установи дату/время эмулятора, под которые хочешь записать активность (Settings → System → Date & time, выключи Set time automatically). Активность сохраняется под текущей датой/временем устройства.

2. На эмуляторе открой фитнес-приложение, стартуй запись GPS-активности.

3. Сразу запусти скрипт:

   ```bash
   python gpx_player.py path/to/track.gpx
   ```

4. Скрипт будет идти столько же, сколько длится трек в GPX (по таймстампам). На экране выведет:

   ```
   [+] Исходно в GPX: 33 точек.
   [+] После интерполяции: 870 точек.
   [+] Высоты: 181.1 – 189.4 м, перепад 8.3 м.
   [+] Длительность: 29.1 мин (проигрыш ~29.1 мин)
   [+] Подключено к эмулятору.
   [+] Pressure-сенсор доступен, барометр будет симулироваться.
   ...
   [+] Трек проигран.
   ```

5. По окончании — Stop в приложении, сохрани активность.

## Как это работает

Эмулятор Android слушает консольные команды на TCP-порту (`5554` по умолчанию). После аутентификации можно слать:

- `geo fix <lon> <lat> <ele>` — GPS-координаты с высотой
- `sensor set acceleration <x>:<y>:<z>` — данные акселерометра
- `sensor set gyroscope <x>:<y>:<z>` — данные гироскопа
- `sensor set pressure <hPa>` — атмосферное давление

Скрипт открывает два независимых сокетных соединения с консолью. Одно используется в основном потоке для отправки GPS-точек и давления, второе — в фоновом потоке для непрерывной симуляции акселерометра/гироскопа на частоте 20 Гц.

### Интерполяция GPX

В реальных GPX-файлах между точками бывают большие временные дыры (например, человек постоял на светофоре и трекер не записывал). Если такие дыры воспроизводить как есть, фитнес-приложение видит длительные «стоянки» и часто отбрасывает следующую точку как невалидный GPS-прыжок, теряя дистанцию.

Скрипт интерполирует траекторию: между каждой парой соседних GPX-точек добавляются промежуточные с шагом 2 секунды, чтобы GPS-поток был плотным и равномерным.

### Симуляция шагов

Акселерометр генерирует синусоидальный паттерн с частотой ~1.9 Гц (≈114 шагов/мин, темп бодрой ходьбы):

- По вертикальной оси: гравитация 9.8 м/с² + амплитуда 3.0 м/с² на основной частоте
- По горизонтальным осям: меньшие колебания со сдвинутой фазой (имитация покачивания)
- На всём этом — небольшой случайный шум

Этот паттерн позволяет софтверным детекторам шагов в фитнес-приложениях засчитывать шаги, даже без аппаратного step counter'а (которого в эмуляторе нет).

### Симуляция барометра

Многие фитнес-приложения берут высоту из барометра, а не из GPS-альтитуды (барометр точнее на ±1 м, GPS — на ±20–30 м). Скрипт по высоте из GPX считает атмосферное давление по формуле стандартной атмосферы:

```
P = 1013.25 · (1 − 0.0065·h / 288.15) ^ 5.255
```

И отправляет в эмулятор. Приложение пересчитывает давление обратно в высоту и рисует рельеф маршрута.

## Параметры скрипта

Все параметры задаются флагами: `--host --port --token --speed --cadence --step --walk-kmh --dry-run` (`python gpx_player.py -h`). Значения по умолчанию — константы в начале `gpx_player.py`:

```python
EMULATOR_HOST = "localhost"
EMULATOR_PORT = 5554
AUTH_TOKEN = "..."

SPEED_MULTIPLIER = 1.0      # множитель скорости воспроизведения
SENSOR_INTERVAL = 0.05      # период отправки данных акселерометра, сек
CADENCE_HZ = 1.9            # частота шагов
INTERP_STEP_SEC = 2.0       # шаг интерполяции между GPX-точками, сек
```

`SPEED_MULTIPLIER > 1.0` ускоряет проигрыш, но фитнес-приложение запишет соответствующую высокую скорость (например, при множителе 5 трек на 29 минут проиграется за 6 минут, и приложение зафиксирует темп ~20 км/ч). Для реалистичной ходьбы оставляй `1.0`.

## Траблшутинг

| Проблема | Причина / решение |
|----------|-------------------|
| `ModuleNotFoundError: telnetlib` | Используй последнюю версию скрипта — она на сокетах, без `telnetlib` (удалён в Python 3.13) |
| `FileNotFoundError: ...gpx` | GPX-файл не в текущей рабочей папке. Используй полный путь или перейди в нужную папку через `cd` |
| Дистанция в Pacer вдвое меньше ожидаемой | Скорее всего `SPEED_MULTIPLIER > 1.0` — приложение отбраковало часть точек как GPS-глюки. Поставь `1.0` |
| Шаги не считаются | Проверь, что приложение использует софтверный step-детектор, а не только аппаратный сенсор (которого нет в эмуляторе) |
| Нет кривой высот | При старте скрипт должен писать «Pressure-сенсор доступен». Если нет — пересоздай AVD с включённым Atmospheric Pressure сенсором |
| Активность на эмуляторе не синкается с телефоном | У некоторых фитнес-приложений кросс-девайс синхронизация работает только в Premium-подписке, либо требует дополнительной диагностики аккаунтов |
